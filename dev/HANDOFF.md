## 사용자 요청 (항상)
- 한국어로 답하기. 파일 여러 개 보낼 땐 사용자가 할 일을 따로 정리.
- 파란색 싫어함, 색약 있음 → 색만으로 구분하지 말 것(아이콘·글자 같이).
- 유료 서비스·Blaze 전환·외부 서비스 추가 금지(별도 승인 없으면). 개인 백업을 외부로 보내지 않기.
- **행동/습관 목록(C.actions)은 사용자가 직접 손봤음 → 사용자가 요청하기 전엔 이름·점수·영역·순서를 바꾸는 마이그레이션 금지.**
- 보스는 끊고 싶은 나쁜 습관 이름으로 만들지 말 것('망설임의 안개' 같은 추상적인 적).
- 매 답변마다 같이 고민: 요구가 틀렸으면 말하고, 더 나은 방법 제안. 근본 재설계가 낫다면 그렇게 말하기.
- 사용자는 공간 낭비를 가장 싫어함: 쓰지 않는 칸은 기본으로 접거나 숨기고, 버튼·입력 줄을 새로 한 줄씩 늘리지 말 것. 화면을 오가거나 여러 번 누르게 하지 말 것.
- 릴리스마다 답변 끝에 **"확인할 곳" 체크리스트**.
- **화면 위치는 자세하고 정확하게(11/14 사용자 요청)**: 아이디어·확인할 곳·설명에서 '어디'를 말할 땐 화면 → 칸 → 단추 순서로 가는 길을 다 적기(예: '홈 → 전투 카드 HP 숫자 누르기 → 최근 7일 줄 펼치기 → ○ 점수 0인 기록 칩'). '0점 칩 옆' 같은 짧은 말은 사용자가 못 찾음.
- **베타에만 올린 릴리스는 답변에 베타 링크(https://movienghome.github.io/habit-quest/beta/)를 같이 줄 것**(11/13 사용자 요청. 본 앱에 같이 올렸을 땐 본 앱 링크).
- **새 채팅으로 옮기는 게 좋을 때는 항상 말해 주기** — 그때 지금 질문의 답·추가 요청을 새 채팅에 적어도 되는지도 같이.
- **사용량 한도 대비(11/12, 사용자가 '알아서 하라'고 함 — 묻지 말고 수행)**: 한도 소진으로 작업이 날아가도 복구된 사용량을 낭비하지 않게.
  1. 묶음이 크면(항목 3개 이상) **항목 하나(또는 서로 붙은 둘)가 시험을 통과할 때마다 바로 커밋·푸시**. 메시지에 `WIP n/m`과 남은 항목. 릴리스 문서(CHANGELOG·TODO·버전 올리기)는 마지막에 한 번 — 중간 커밋은 코드(+ 아래 '진행 중' 줄)만.
  (⚠ 11/12 v7.9 WIP 1에서 이 파일 102줄이 잘려 나갔다가 복구함 — 이 파일은 **부분 치환(str_replace/replace)만**, 통째 덮어쓰기 금지. 커밋 전 `wc -l dev/HANDOFF.md`가 갑자기 줄었는지 볼 것. 11/12 밤 v8.0에서도 '## 진행 중' 글자가 규칙 2번 안에 있는 걸 `index`로 잘라 29줄이 됨 — 자를 땐 `rindex`와 블록 첫 줄까지 붙인 문자열로.)
  2. 중간 커밋마다 이 파일 맨 아래 **`## 진행 중`** 을 갱신: 어디까지 끝냈고(커밋 해시), 다음 항목이 무엇이고, 건드릴 함수·파일, 시험 상태. 끝나면 그 칸을 비움.
  3. 대화가 길어지거나(큰 빌드·시험 반복) 한도가 가까워 보이면 **사용자 말을 기다리지 말고 그 자리에서 커밋·푸시하고 '새 채팅에서 HANDOFF만 읽고 시작하세요'라고 안내**. 새 채팅은 HANDOFF의 '진행 중'을 보고 이어가며, CHANGELOG·TODO는 필요한 항목만 찾아 읽음(전체 읽기 금지 — CHANGELOG는 100KB 넘음).
  5. **푸시가 막히면(11/23 v12.0이 로컬 커밋만 남기고 작업공간과 함께 사라진 일)**: 쓰기 권한(`add_repo` push)이 거부되면 **코드 작업을 시작하기 전에 멈추고** 사용자에게 승인을 요청. 이미 작업했다면 끝내기 전에 `git format-patch -1 --stdout`을 **프로젝트 문서(`project_write`, 예 `notes/unpushed-vX.Y.patch`)에 저장**해 두고 사용자에게 알림 — 로컬 커밋은 채팅이 끝나면 사라짐. 다음 채팅은 그 patch를 `git am`으로 먼저 적용.
  4. **시작할 때 요청이 현재 모델 수준·노력 수준에 안 맞으면 그것부터(그 말만) 짧게** 하고 알맞은 모델·노력 수준을 추천.

## 핵심 설계
- **점수는 행동 카드에만.** XP=성장(레벨) · 골드=현실의 돈·자원 · 컨디션=지금의 몸과 마음. 해당 없으면 0. 카드 없는 할 일은 크기·중요도 점수(C.taskXP), 골드는 경제 영역이거나 t.px일 때만(v7.1).
- **행동 카드** = 무엇을 하면 몇 점 · **할 일** = 언제 할지(한 번/반복) · **습관** = 카드 + 그 카드에 이어진 반복 할 일(↻) · **일퀘** = 반복 할 일의 ☑(그 일이 뜨는 날만).
